# PlinyCode roadmap (Q4 2026: 6 waves, ~12 weeks)

## Context

PlinyCode (0.2.3-test.2, first release 2026-09-22) has spent its first month on free-model reliability (router, completion guard, Kimi tool-call ids), Cline removal (~35 PRs), agent-quality features (ask mode, plan files, reviewer, advisor, side questions), the CI Board and Pipelines views, repo memory, and the context-management waves (#124-#135). No roadmap exists in the repo (`plans/` is empty, no doc has a future-work section).

Three read-only audits on 2026-10-16 found the engine (`sdk/packages/*`) disciplined and well tested, while the biggest gaps are in **what the agent can do** and **how we know it works**:

- **Agent capability.** No code intelligence although the extension runs inside VS Code with language servers: no definition/references/symbols tools, `list_code_definition_names` is an alias of `search_codebase`, only the edited file's diagnostics come back after an edit. Isolation exists only for the CI Board (worktrees); normal tasks share checkpoints and the reviewer diff per folder. Background commands hand off after 5 minutes and cannot be killed (`cancelBackgroundCommand` is a stub at `apps/vscode/src/sdk/SdkController.ts:1175`). The Web Search toggle does nothing on Pliny. Only 5 paid hosted models take images. Sub-agents show only a counter row; configured agents have no UI.
- **Reliability and evaluation.** Routes are tuned on n=1 probes and anecdotes; the call log lacks real tokens/cost and task success; the classifier has no labelled set. A 900-line VCR recorder (`sdk/packages/shared/src/vcr.ts`) exists but is wired nowhere. No per-session trace, no log file (`extension.ts:758` passes a no-op sink), no diagnostics bundle. Three nested retry layers each have their own budget. 44 of 74 gateway tests are skipped; two extension vitest files never run.
- **Debt.** ~5.5k lines of disabled agent-team code, two hook engines, two MCP settings locks (core's sync variant blocks the host with `Atomics.wait`), two `ModelInfo` types and two copies of the Pliny helpers, three event-translation layers ending in a 57-case `ChatRow` switch with 10 unguarded `JSON.parse` calls during render, `SdkController.ts` at 2,060 lines and most churned, the full transcript rewritten after every model call.
- **Workflow.** Pushes to `stage` run only docs-check; no CI cache; release is manual on a laptop; `-test.N` ticks are committed per PR and conflict; pre-commit skips `sdk/`; launch config disables the wrong extension id.

**Decisions (2026-10-17):** weight **agent capability** most; ~3 months in 5-6 themed waves of small single-theme PRs to `stage`; **delete agent teams** but keep `spawn_agent`/configured agents; **unify hooks on the engine's `hook-file-hooks.ts`** and delete the extension's Cline-era stack; the public web is reachable through a proxy, so a real `web_search` tool is in scope.

**Outcome.** By end of Q4 the free router solves tasks a weak model cannot solve by regex alone (symbol navigation, isolated worktrees, managed background processes, web lookup, images); every router or prompt change is measurable against a replayable task corpus; a bad run is debuggable from an exported bundle; the codebase has one implementation per concern; 0.3.0 ships from a tag-triggered workflow.

## Ground rules

- **Extension tools are plain `AgentTool`s** (`sdk/packages/shared/src/agent.ts:226`) appended to `config.extraTools` / `subAgentExtraTools` in `prepareStartSessionInput` (`apps/vscode/src/sdk/vscode-session-host.ts:146-187`) by `createVscodeExtraTools` (`apps/vscode/src/sdk/vscode-runtime-builder.ts:72-158`, which already adds MCP, DevOps, `run_commands`, `wait`, `update_todo_list`). Every new tool: one file under `apps/vscode/src/sdk/<area>/`, registered there, an approval line in `sdk-tool-policies.ts`, a case in `message-translator/tool-mapping.ts` (unknown tools fall to the `default:` passthrough), a `ClineSayTool.tool` value in `shared/ExtensionMessage.ts` + proto enum, a `ChatRow.tsx` render, a section in `docs/agent-tools.md`. Tool descriptions stay under ~120 words (schema tokens cost every request on free models).
- **Wave = 2 weeks = 5-7 single-theme PRs to `stage`**, never stacked (base must show `stage` before merge). Engine PRs (`sdk/**`) land before the extension PR that uses them, each with `bun run build:sdk`. Each wave carries agent items (A), one reliability/eval item (R), one workflow item (W), one debt item (D).
- `-test.N` ticks per PR until W3 moves them to CI. Windows is the primary platform: test process kill, worktree paths, hook toggles on the Windows CI leg.

## Wave 1 (weeks 1-2): see what the agent does, let it see the code

**Goal.** Navigate code through language servers instead of regex; every session leaves a trace and a log; CI runs on `stage`; agent teams are gone.

**A1. `code_intel` v1** — new `apps/vscode/src/sdk/code-intel/{code-intel-tool.ts, code-intel-format.ts}` + `apps/vscode/src/hosts/vscode/code-intel-source.ts` (the only file importing `vscode`; same split as `sdk/edit-problems.ts` / `hosts/vscode/edit-diagnostics.ts`). Two tools, not six (free models mis-fill wide schemas):
- `find_symbol({ query, path?, kind? })`: with `path` → `vscode.executeDocumentSymbolProvider` (flattened `kind name  path:line`); else `vscode.executeWorkspaceSymbolProvider`, cap 40.
- `code_navigate({ action: "definition"|"references"|"hover", path, symbol, line? })`: resolve the position by locating `symbol` as an identifier in the document text nearest `line` (model never computes columns), then `executeDefinitionProvider` / `executeReferenceProvider` / `executeHoverProvider`; hover reduced to code-fenced signature lines.

## Cross-wave risks and sequencing

- **Engine/extension coupling.** Every core change (D1, D3, A9, D5, R6) needs `bun run build:sdk` and ships as its own PR before the extension PR that uses it; never bundled with webview work.
- **Pliny is internal.** Live evals (R5) and un-skipped gateway tests (R8) need a self-hosted runner or stay developer-triggered; offline cassettes are the CI contract.
- **Windows first.** Process kill through ConPTY, worktree path lengths, hook toggles, the VSIX job: test on the Windows matrix leg.
- **Token budget of new tools.** A1/A3/A10 add schema tokens to every request; R7's `tools` bucket makes the cost visible. Keep descriptions short and prefer few tools with an `action` argument.
- **Dependencies.** A5 (worktree v1) before A12/A13/A18; R1 trace before R2 bundle; R3 cassettes before R5/R8; D1 before D6 (knip surface); W3 tick scheme before W6 release.
